---
description: 前回セッションの引き継ぎ（diary）を読んで、作業を再開できる状態にする
---

`.claude/diary/` に記録された前回までの引き継ぎを読み、いまの状態を把握して作業を再開する。

## 手順

1. 最新の diary を読む。引数で日付や件数が指定されていれば、それに従って遡る。

   ```bash
   ls -1 .claude/diary/*.md | sort | tail -3
   ```

   ファイル名は `YYYY-MM-DD-HHMM.md`（UTC）なので、辞書順が時系列順になる。
   既定では最新 1 件を読む。`$ARGUMENTS` に数字があればその件数、日付があれば
   その日以降を読む。

2. **diary に書かれている状態が今も正しいかを確かめる。** diary は書かれた
   時点のスナップショットであり、その後に何かが変わっている可能性がある。
   最低限、次を実測する。

   ```bash
   git log --oneline -5
   git status --short
   ```

   diary の front matter にある `commit` と現在の HEAD がずれていたら、
   その差分が diary に反映されていないということ。`git log` で埋める。

3. 未完了として書かれている項目については、**本当に未完了かを確かめてから**
   再開する。diary の記述を鵜呑みにしない。このリポジトリの原則どおり、
   状態は実測で確認する。

4. 把握した内容をユーザーに短く報告する。長い復唱はしない。伝えるのは次の 4 点。

   - 前回どこまで進んだか
   - いまの状態（ブランチ、未コミットの有無、検証の通過状況）
   - 次にやる予定だったこと
   - diary の記述と実測がずれていた点（あれば）

## diary が無い場合

`.claude/diary/` が空なら、それは初回セッション。その旨を伝えて、
通常どおり作業を始める。存在しないものを推測で補わない。

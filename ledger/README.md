# 情報源台帳（Data Source Registry）

信頼できる日本のデータ提供源を、**推測を混ぜずに**記録するための台帳。

## 設計の核: 証拠レベル

台帳の全行に `evidence_level` を必須で付ける。**これが無い記録は台帳に入れない。**

| レベル | 意味 | 記録に必要なもの |
|---|---|---|
| `E0` | 存在を聞いただけ | — |
| `E1` | **二次情報** — 第三者の記述（キュレーションリスト・記事・検索結果）に基づく。一次情報は未読 | 出所URL・参照日 |
| `E2` | **一次情報（文書）** — 提供元の公式ページ／公式ドキュメントを直接読んだ | 公式URL・参照日 |
| `E3` | **実行確認** — 実際に接続して応答を得た | 実行日時・**実行環境**・コマンド・応答の断片 |
| `E4` | **反復確認** — 別日に2回以上、同手順で再現した | 上記＋再現日 |

### 最重要ルール

> **接続手順（`connection_procedure`）は `E3` 以上でなければ書かない。**

E2以下で書けるのは「手順**候補**」まで。公式ドキュメント通りに書いた手順は、
実行していない限り**推測**である。本プロジェクトはこれを実証済み —
Jグランツ公式MCPは手順通りに起動して `tools/list` まで通ったが、
API呼び出しは `403` で失敗した（原因は実行環境の egress ポリシー）。
**ドキュメントは「動くはず」しか教えてくれない。**

### 実行環境を必ず併記する

`E3` の失敗は、**データ源の属性ではなく実行環境の属性**でありうる。
`verified_env` 列に実行環境IDを記録し、`docs/environments.md` で定義する。
環境が違えば結果が変わる記録は、環境を書かなければ嘘になる。

## 2層構造

`providers.csv`（提供元）と `sources.csv`（提供単位）を分ける。
e-Stat は提供元1件だが、その下のデータセットは22万件規模。
**「提供元1行」では粒度が粗すぎて接続手順が書けない。**

## 「頻度」は2種類ある

- `data_update_freq` — データ自体の更新頻度（例: 月次、年次、随時）
- `spec_watch_url` — **提供方式の変更**（API仕様変更・廃止）の告知先

後者を記録しないと台帳は黙って腐る。過去に終了したサービスは多い。

## 「信頼性」を隠れフィルタにしない

「信頼性が高いものだけ載せる」と選別基準が暗黙になる。**基準を列にして記録し、
判断は台帳の読み手に渡す。** `provider_type` / `is_primary_source` /
`license` / `attribution_required` / `continuity_note` がその役割。

## 記録規約

- 欠損は空欄にせず `UNKNOWN`（調べていない）と `NOT_PROVIDED`（提供元が公開していない）を区別する
- `recorded_at` / `last_verified_at` / `reverify_after` を必ず入れる。台帳は資産ではなく生鮮品
- 政府データは**出典明記が義務のものが多い**。`attribution_required` を空欄にしない
